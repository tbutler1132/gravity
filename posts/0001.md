The foundation of this project is a small text file that declares what kinds of things exist.

In software, a file like this is called a schema. A schema defines the shape things are allowed to take and what a valid instance of each kind must have. Everything downstream is built against those definitions instead of fuzzy, unspoken ones.

I don't think of this file as just a technical artifact. It is more like a grammar. Before a community can create things together, it needs a shared understanding of what exists. It is an agreement that sits underneath every other agreement. Usually that agreement stays implicit, and implicit agreements drift. Writing this grammar down as a canonical, enforceable text is what turns the agreement into real infrastructure. Something that can be referenced, built on, and argued against.

Concretely, the file currently defines two types: Weeks and Cycles. Before naming any of the things that will be created, the grammar names the time they will be made in. Traditionally, communities are constituted by shared time before shared things.

A Week is the grid: uniform, repeating, the same size every time. That sameness is the point. A Week exists to carry rhythm like rituals, check-ins, and habits that only work because the interval never changes. You feel a sense of belonging because your time has the same shape as everyone else's.

A Cycle is the arc: time defined by its purpose. A Cycle exists to produce one primary creative output.
